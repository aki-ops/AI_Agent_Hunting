# PEAK ABLE Table: Joomla RCE Web Compromise
*Hypothesis: Joomla RCE web compromise (BOTS v1 real attack). Attacker scans and exploits Joomla search/mailto components on imreallynotbatman.com.*
| ABLE Element |  |
| --- | --- |
| Actor | Unspecified external attacker; BOTS v1 real attack with no named group. Hunt is behavior-based for opportunistic scanning and exploitation of Joomla, not actor-specific IOCs. |
| Behavior | MITRE ATT&CK T1190 Exploit Public-Facing Application: scanning/probing followed by exploitation of Joomla search and mailto components to achieve web compromise / RCE. Expected observable chain: web_request, exploitation. Hunt one piece at a time: find scan URIs first, then exploitation attempts from same host/ip in tight time window. |
| Location | Perimeter / egress web activity to external internet-facing site imreallynotbatman.com as seen from internal hosts. In CDB terms: host values that generate web_request telemetry with domain pointing to imreallynotbatman.com; associated ip and timestamp for egress. If Joomla were hosted internally, also DMZ web server, but local telemetry only shows requester side. |
| Evidence | Data source: CDB SQLite table events filtered to native_type EQUALS web_request (39010 rows, 2016-08-01T00:01:01Z to 2016-08-28T23:54:58Z). Relevant fields: domain holds site, cmdline holds text site=<host> uri=<path>, plus timestamp, host, ip, port for pivots. Detection drafts as literal case-insensitive predicates for deterministic executor, one predicate per step: domain EQUALS imreallynotbatman.com to isolate compromised site; cmdline CONTAINS /joomla/ to isolate Joomla component paths; cmdline CONTAINS search and cmdline CONTAINS mailto to separate components; additional cmdline CONTAINS for exploit strings to separate scan vs exploit. Pivot on host, ip, timestamp to chain scan to exploit. |
Notes:
- Executor constraint: each PoC step must be one literal predicate (field, operator, value) over timestamp, event_id, native_type, host, user, pid, ppid, cmdline, image, ip, port, domain, file_path, action, status, raw_ref with operators EQUALS, CONTAINS, STARTS_WITH, ENDS_WITH, MATCHES, EXISTS; EQUALS, CONTAINS, STARTS_WITH and ENDS_WITH are case-insensitive. Write any SPL only as equivalent detection draft using those predicates plus pivots on host, user, ip and time.
- Coverage gap: CDB web_request only stores domain and site/uri in cmdline with no HTTP method, headers, user-agent, response status/body, and no server-side Joomla execution logs. Scanning to imreallynotbatman.com can be proven, but RCE / web compromise success cannot be confirmed from available data alone.
- Authentication (4624), process_creation (4688, 1), smb (5140, 5145, 4648), dns tables do not directly evidence web exploitation; use them only for post-exploit pivots by host, user, ip and time if web_request finds a suspect source.
