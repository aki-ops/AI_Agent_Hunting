# PEAK ABLE Table: Brute Force - Password Guessing Against a Server
*Hypothesis: Brute force login against public-facing server. Repeated failed authentication events targeting user accounts on a host. The encoded cmdline row carries 'Logon Failed' for failed attempts.*
| ABLE Element |  |
|---|---|
| Actor | Unspecified external attacker - no named actor in hypothesis or research; any opportunistic external actor conducting password guessing, consistent with MITRE ATT&CK T1110 - Brute Force |
| Behavior | T1110 Brute Force password guessing as authentication_failure_burst: repeated failed authentication events targeting user accounts on a single host, per BOTS v1 brute-force phase and Splunk SURGe PEAK hypothesis-driven hunting; focus on one behavior burst at a time, including targeting of privileged account admin |
| Location | Public-facing / internet-facing servers: the host receiving the authentication attempts (internal target) and perimeter ingress point; scope in telemetry via host and pivot by ip, user and time to isolate source to target relationship |
| Evidence | Local telemetry CDB SQLite table events, native_type EQUALS authentication (event_id 4624, 579580 rows 2016-08-01 to 2016-08-28). Examine cmdline, user, host, ip, timestamp, action. Positive would look like a burst/cluster on same host in a short time window of: cmdline CONTAINS Logon Failed with user EQUALS admin, with repeated timestamps and potentially single ip. Auth rows encode outcome as text such as Logon Success user=.. ip=.. in cmdline and outcome in action, so research relies on the encoded cmdline CONTAINS Logon Failed predicate. All hunt steps must be single literal field/operator/value predicates (EQUALS, CONTAINS, STARTS_WITH, ENDS_WITH, MATCHES, EXISTS, case-insensitive for EQUALS/CONTAINS/STARTS_WITH/ENDS_WITH) plus pivots on host, user, ip and time; any SPL is detection draft equivalent only |
- Executor constraint: hunts run through deterministic executor, not by LLM - LLM never creates or edits evidence, so use only literal predicates over timestamp, event_id, native_type, host, user, pid, ppid, cmdline, image, ip, port, domain, file_path, action, status, raw_ref
- Public-facing status cannot be answered from events table alone - host, domain, and ip show target/source but there is no network zone / asset inventory tag to confirm internet-exposed server; need external asset context
- Scope limitation: user EQUALS admin is an analyst-authored example for privileged targeting; hunting only admin will miss bursts against other accounts - pivot by user to assess password guessing vs password spray
- Success determination requires correlation: burst of Logon Failed alone shows attempt, confirming compromise requires follow-on Logon Success / action change on same host + user + ip in time order, and tooling / password values are not visible in available fields
